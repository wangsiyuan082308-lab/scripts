## 1. 概述

### 1.1 背景
当前 `scripts` 中的财务模块已经从“报表展示页”演进为“财务任务工作台”，承担已有报表查看、新建任务、重新生成、上传 Excel 保留等能力。  
在最近一轮简化交互时，页面为了满足“一个搜索项 + 表格”的目标，过度删除了结构化筛选入口，导致业务上仍存在的筛选维度在 UI 中消失。

### 1.2 目标
- 明确财务模块当前真实定位：轻量财务工作台，而非复杂驾驶舱
- 还原哪些筛选维度是必要能力，哪些属于冗余
- 给出“简洁但不丢业务语义”的最小筛选方案

### 1.3 成功指标
- [ ] 财务列表页在保持 `SimpleTemplate` 规范的前提下恢复最小必要筛选
- [ ] 用户可明确按月份、任务状态、盈利状态、门店配置状态筛选列表

## 3. 功能需求

### FR-001：财务页应保持轻量工作台形态
- **描述**：当用户进入财务模块时，系统应展示一个基于 `SimpleTemplate` 的列表页，用于查看报表和管理任务，而不是额外的统计卡片或多子页结构。
- **优先级**：必须有
- **依赖**：`SimpleTemplate`
- **验收标准**：
  - [ ] AC-1：页面仅保留搜索区、表格区、任务操作入口
  - [ ] AC-2：不再出现月度汇总、毛利异常、结果核对的独立子页入口

### FR-002：财务页应保留最小必要筛选
- **描述**：当用户查看财务列表时，系统应提供最小但完整的结构化筛选，而不是只保留关键词搜索。
- **优先级**：必须有
- **依赖**：财务列表数据模型
- **验收标准**：
  - [ ] AC-1：支持 `关键词`
  - [ ] AC-2：支持 `月份`
  - [ ] AC-3：支持 `任务状态`
  - [ ] AC-4：支持 `盈利状态`
  - [ ] AC-5：支持 `门店配置状态`

### FR-003：财务页应继续支持任务工作流
- **描述**：当用户在列表页操作财务结果时，系统应支持新建任务、基于现有报表重新生成、保留已上传 Excel。
- **优先级**：必须有
- **依赖**：本地任务仓库、报表详情
- **验收标准**：
  - [ ] AC-1：支持新建财务任务
  - [ ] AC-2：支持基于已有报表重新生成
  - [ ] AC-3：已上传的 4 类计算 Excel 可保留并复用

## 4. 非功能需求

### NFR-001：一致性要求
- **类型**：一致性
- **描述**：财务列表页应复用项目既有列表页规范
- **指标**：使用 `SimpleTemplate`，搜索项必须有 `label`

### NFR-002：交互复杂度要求
- **类型**：可用性
- **描述**：筛选应控制在一行内联布局，桌面端不做重型搜索面板
- **指标**：桌面端默认一行显示，移动端允许自然换行

## 5. 用户故事

### US-001：定位问题结果
- **作为** 财务运营人员
- **我想要** 按月份和状态筛选财务结果
- **以便** 快速找到需要核查或重生成的报表
- **验收标准**：
  - [ ] 可以筛出某月的报表/任务
  - [ ] 可以筛出亏损门店或待重生成任务

### US-002：发起重生成
- **作为** 财务运营人员
- **我想要** 从已有报表直接发起重新生成
- **以便** 复用旧结果和旧输入，不重复录入
- **验收标准**：
  - [ ] 列表操作区可直接发起重新生成
  - [ ] 已保留的 Excel 附件可继续复用

## 6. 范围定义

### 6.1 范围内
- 财务列表页的信息架构审计
- 列表筛选项恢复方案
- `SimpleTemplate` 规范落地

### 6.2 范围外
- 财务计算口径重写
- `scripts-backend` 真实生成链路接入
- 月度汇总/毛利异常等独立分析页恢复
