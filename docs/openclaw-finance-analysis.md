# OpenClaw 财务技能梳理

本文梳理 `~/.openclaw/workspace/skills/oby-finance-analyzer` 的真实财务能力，目标是把“脚本知识”沉淀成 `scripts` 可复用的中台认知。

## 1. 结论

`oby-finance-analyzer` 不是简单的 Excel 转换器，而是一条完整的财务报表生成链路：

1. 自动识别月度原始文件
2. 兼容牵牛花与翱象两套数据源
3. 统一生成门店级财务报表
4. 自动补齐推广费、固定成本、加盟费
5. 读取上月报表做环比
6. 生成月度门店汇总和高低值标色

真正的业务入口在：

- [SKILL.md](/Users/mac/.openclaw/workspace/skills/oby-finance-analyzer/SKILL.md)
- [oby_finance_report.py](/Users/mac/.openclaw/workspace/skills/oby-finance-analyzer/oby_finance_report.py)
- [finance_config.py](/Users/mac/.openclaw/workspace/skills/oby-finance-analyzer/finance_config.py)
- [store_config.json](/Users/mac/.openclaw/workspace/skills/oby-finance-analyzer/store_config.json)

## 2. 文件与职责

### 2.1 主入口

- `oby_finance_report.py`
  - 自动发现输入文件
  - 读取牵牛花和翱象数据
  - 按统一口径构造门店指标
  - 生成单门店报表
  - 生成月度门店汇总
  - 写入环比和 Excel 公式

### 2.2 配置层

- `finance_config.py`
  - 管理费率 `2%`
  - 加盟费 `20000 / 12`
  - 上月报表继承规则
  - 推广费文件识别规则
  - 门店映射读取辅助函数

### 2.3 门店配置

- `store_config.json`
  - 门店简称
  - 美团门店 ID
  - 饿了么门店名称
  - 固定成本默认值

### 2.4 工作流执行

- `lobster_runner.py`
- `oby-finance-report.lobster`

它们负责把财务生成流程包装进 Lobster 工作流，但业务口径不在这里，核心仍在 `oby_finance_report.py`。

## 3. 输入与前置条件

## 3.1 月份目录

默认从：

```text
~/Downloads/财务报表/YYYY-MM/
```

读取当月原始文件。

## 3.2 主数据文件识别

主数据优先识别以下文件名：

1. `经营分析PC端*`
2. `牵牛花*`
3. `经营分析.xlsx`
4. `经营分析导出门店盈亏*`
5. `经营分析*`
6. `导出财务分析订单数据*`

同时会主动排除：

- `推广`
- `翱象`
- `翱翔品质仓`
- `门店总表`
- `毛利异常`
- `关键指标`

## 3.3 翱象文件识别

当文件名包含以下关键字时视为翱象数据：

- `翱翔`
- `翱象`
- 文件名以 `翱` 开头

## 3.4 推广费文件识别

必须放在同月目录下：

- `*饿了么*推广*.xlsx`
- `*美团*推广*.xlsx`

其中：

- 饿了么按 `分店名称` 匹配
- 美团按 `门店id` 匹配

## 3.5 上月环比前置条件

只有当上月报表存在时，门店报表右侧环比才有真实上月值。

兼容两类历史文件：

- `YYYY-MM月-门店简称-门店报表.xlsx`
- `YYYY-MM月-门店简称-财务报表.xlsx`

如果找不到上月文件，会以 `上月 = 0` 降级展示。

## 3.6 特殊输入

- 安吉店可额外传入 `anji_mt_orders`
  - 用于计算 `美团打包费补贴 = 美团订单量 × 0.3`

## 4. 数据源口径

## 4.1 牵牛花

关键字段来源：

- `账单-订单量`
- `收入-总收入`
- `经营指标-实付金额`
- `收入-商品原价总金额`
- `收入-配送收入`
- `收入-商品包装费`
- `收入-营销活动费用`
- `费用-三方配送费`
- `费用-配送服务费`
- `费用-佣金`
- `费用-公益捐款`
- `税率相关-商品成本`
- `成本-线下销售商品成本`
- `税率相关-线上毛利`

补充规则：

- 商品成本优先取 `税率相关-商品成本`
- 若为 0，则回退到 `成本-线下销售商品成本`
- 配送费 = `三方配送费 + 配送服务费`

## 4.2 翱象

翱象会做字段归一化，典型映射如下：

- `有效订单量 -> 订单数量`
- `预计线上收入 / 总收入 -> 总收入`
- `用户实付金额 / 有效订单金额 -> 实收交易额`
- `订单金额 / 商品原价 -> 商品原价总金额`
- `应收配送费 / 配送费原价 -> 配送收入`
- `商家包装费 / 包装费原价 -> 商品包装费`
- `营销活动费用 / 商家活动费用 -> 营销活动费用`
- `平台配费用 + 自配送费用 -> 配送费`
- `佣金 / 平台费用 -> 平台佣金`
- `商品成本 / 商家采购成本 -> 商品成本`

特别注意：

- 翱象 `净利润` 或 `预计毛利` 已经扣过推广费
- 脚本为了统一报表，会先算：
  - `线上毛利 = 翱象净利润 + 翱象推广费`

## 5. 核心计算口径

以下口径由 `_build_rows()` 统一构造。

### 5.1 订单平均价

```text
订单平均价 = 总收入 / 订单数量
```

### 5.2 营销活动费用费率

```text
营销活动费用费率 = 营销活动费用 / 商品原价总金额
```

### 5.3 管理费

```text
管理费 = 实收交易额 × 2%
```

### 5.4 推广费

```text
推广费 = 饿了么推广费 + 美团推广费
```

其中：

- 饿了么推广费 = 同月饿了么推广清单按门店汇总
- 美团推广费 = 同月美团推广清单按门店 ID 汇总绝对值

### 5.5 线上毛利率

```text
线上毛利率 = 线上毛利 / 总收入
```

### 5.6 净利润

```text
净利润 = 线上毛利
      - 推广费
      - 房租物业
      - 加盟费
      - 水电杂项
      - 人力成本
      - 办公杂项
      - 管理费
```

安吉店若传入美团订单量，还会额外加：

```text
+ 美团打包费补贴
```

### 5.7 净利润率

```text
净利润率 = 净利润 / 总收入
```

## 6. 固定成本规则

当前报表固定成本优先级不是完全一致的两套来源，要注意：

### 6.1 实际生成门店报表时

`oby_finance_report.py` 当前优先读取：

- `store_monthly_data.json`
- 若当月没有，则回退上月
- 再没有则用默认值

### 6.2 配置层理论规则

`finance_config.py` 里还有一套：

- `store_config.json`
- 上月报表继承
- 默认值兜底

这说明脚本历史上经历过口径演进。当前真实执行主链以 `load_store_monthly_costs()` 为主，`store_config.json` 更多承担：

- 门店映射
- 初始固定成本
- 推广费匹配辅助

## 7. 输出产物

## 7.1 单门店报表

输出到：

```text
~/Downloads/财务报表/门店简称/YYYY-MM月-门店简称-门店报表.xlsx
```

特点：

- 左侧主报表

- 单元格里保留 Excel 公式

## 7.2 月度门店汇总

输出到：

```text
~/Downloads/财务报表/YYYY-MM/YYYY-MM月-门店模板汇总.xlsx
```

特点：

- 同一指标横向对比所有门店
- 收入类高值标绿，低值标黄
- 成本类低值标绿，高值标黄

## 7.3 毛利异常汇总

当前目录中也会保留 `毛利异常汇总.xlsx`，可以作为经营风险补充视图。

## 8. 校验点

把财务能力接入 `scripts` 时，至少应校验以下内容：

### 8.1 输入校验

- 月份目录是否存在
- 主数据文件是否识别成功
- 推广费文件是否缺失
- 门店映射是否齐全
- 上月报表是否存在

### 8.2 口径校验

- 管理费是否等于实收交易额的 2%
- 净利润是否等于公式展开结果
- 费率类字段是否按百分比展示
- 牵牛花和翱象门店是否混入重复门店

### 8.3 展示校验

- 老格式 `总表` 是否仍能识别
- 新格式 `单门店报表` 是否优先识别
- 汇总表表头是否能正确抽取
- 无上月数据时是否降级展示

## 9. 当前接入 scripts 的建议

当前 `scripts` 应把 `openclaw` 财务技能视为：

- 规则与报表产物来源
- 不是最终 UI
- 也不是中台最终模型

因此正确接入方式是：

1. `backend-mock` 直接读取 openclaw 报表产物
2. 前端做经营视角展示与解释
3. 后续逐步把口径沉淀到 `scripts` 的统一财务模型

不要直接复制整套 Python 执行逻辑进前端项目，更不要把“页面上传解析”误当成正式财务能力。
